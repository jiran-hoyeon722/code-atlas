# 의존성 도시 — 폭발 반경 설계

- 작성일: 2026-09-30
- 상태: 설계 합의 완료, 사용자 검토 대기
- 선행: `2026-09-29-code-atlas-browser-design.md` (도시 화면)

## 1. 목적

건물(파일)을 고쳤을 때 **간접까지 어디로 번지는지**를 도시 위에서 단계별로 보여 준다. 지금 도시는 직접 연결(아치선)만 보여 주므로 "이 파일을 쓰는 파일을 쓰는 파일"은 알 수 없다.

- 사용자: 자기 레포를 넣은 개발자, 레포를 처음 익히는 팀원.
- 성공 기준: 건물을 고르고 버튼 하나를 누르면 충격파가 단계별로 퍼지고, 패널에 "직접 N · 간접 M · 도시의 P% · 최대 K단계"와 단계별 파일 목록이 나온다. 기존 도시 동작은 버튼을 누르기 전까지 하나도 달라지지 않는다.

기능 확장 로드맵(폭발 반경 → 기능 투어 → 위험 지도 → 타임랩스) 중 첫 번째이며, 나머지는 각자 별도 설계 문서로 진행한다.

## 2. 범위

| 포함 | 제외 |
|---|---|
| 도시 화면의 패널 버튼 「💥 폭발 반경」 | 그래프 뷰·탐색기 연동 |
| "나를 쓰는 곳" 방향의 연쇄(역방향 BFS) | 반대 방향("내가 쓰는 것"의 연쇄) |
| 단계별 충격파 애니메이션, 동작 줄이기 대응 | 단계 수 제한 설정 |
| 「타입 참조 제외」 토글 | 고유 라우트 수 계산(엔진·캐시 변경 필요) |
| 딥링크 `#city&file=…&blast` | 엔진·캐시 변경 |

## 3. 사용자 흐름

1. 건물을 누르면 지금과 같이 직접 참조 아치선과 패널이 뜬다.
2. 패널 actions 줄(코드 보기 옆)에 「💥 폭발 반경」 버튼이 있다.
3. 누르면:
   - 선택 건물 발밑에서 원형 충격파 고리가 바깥으로 퍼진다.
   - 1단계(직접 나를 쓰는 곳) 건물이 먼저 붉게 짧게 흔들리며 물들고, 약 0.4초 간격으로 2단계, 3단계… 순서로 번진다.
   - 단계가 멀수록 옅은 색: 1단계 진한 빨강 → 중간 주황 → 먼 단계 노랑 (최대 단계 기준 보간).
   - 영향 없는 건물은 기존 선택 때처럼 어둡게.
   - 기존 직접 참조 아치선은 숨긴다(충격파와 겹쳐 읽기 어려움).
   - `prefers-reduced-motion: reduce` 이면 애니메이션 없이 최종 색만 바로 칠한다.
4. 패널 상단(지표 아래)에 폭발 반경 섹션:
   - 요약: `직접 3 · 간접 41 · 도시의 12% · 최대 5단계`
   - `영향권 중 라우트가 직접 쓰는 파일 N개` (라우트 참조 > 0 인 영향 파일 수)
   - 「타입 참조 제외」 체크박스 — 바꾸면 즉시 다시 계산하고 애니메이션을 다시 재생
   - 단계별 파일 목록(단계 제목 + 파일 버튼, 단계마다 최대 40개 + "외 N개"). 누르면 그 건물로 이동(선택이 바뀌므로 폭발 반경은 해제)
   - 영향 파일이 0개면 "이 파일을 쓰는 곳이 없습니다 — 고쳐도 다른 파일에 번지지 않습니다"
5. 해제: 버튼 다시 누름, 패널 닫기, `Esc`, 다른 건물 선택.
6. 딥링크: 켜진 상태에서 해시는 `#city&file=<경로>&blast` (코드 보기와 함께면 `&code&blast`). 해시로 들어오면 해당 건물을 선택하고 폭발 반경을 켠 상태로 시작한다.

## 4. 계산 규칙

`src/features/city/blast.ts` — DOM·three.js 를 쓰지 않는 순수 함수.

```ts
export interface BlastResult {
  depth: Int32Array;      // 파일별 단계, 시작 파일 0, 닿지 않으면 -1
  levels: number[][];     // levels[k] = k+1 단계 파일 인덱스 (시작 파일 제외)
  maxDepth: number;       // 영향 없으면 0
  affected: number;       // 시작 파일 제외 영향 파일 수
  routeFiles: number;     // 영향 파일 중 routeRefs > 0 인 수
}
export function blastRadius(
  count: number,
  edges: Architecture['edges'],
  start: number,
  routeRefs: ArrayLike<number>,
  opts: { skipTypeOnly: boolean },
): BlastResult;
```

- 참조 `[from, to]` 는 "from 이 to 를 쓴다". 폭발은 to → from 방향으로 퍼진다.
- BFS 이므로 파일마다 **가장 가까운 단계 한 번만** 센다. 순환이 있어도 끝난다.
- 타입 전용 참조: 참조 종류(`kinds`)의 키가 전부 `type`, `type-import` 중 하나인 참조. `skipTypeOnly` 이면 이런 참조는 따라가지 않는다. 실행 참조가 하나라도 섞이면 유지한다.
- 목록 안 순서: 단계 안에서는 fan-in 큰 순 → 이름순 (화면에서 정렬).
- 복잡도 O(파일 + 참조). 버튼을 누를 때마다 계산하고 결과를 저장하지 않는다.
- `도시의 P%` = affected ÷ (전체 파일 − 1), 소수 없이 반올림, 파일이 1개면 0%.

## 5. 화면 구현

| 파일 | 변경 |
|---|---|
| `src/features/city/blast.ts` | 새 파일, 위 계산 |
| `src/features/city/mountCity.ts` | `state.blast: { result, startedAt, skipTypeOnly } \| null`. 버튼·섹션 렌더, `applyColors` 에 단계 색 분기, 렌더 루프에서 경과 시간으로 각 단계 표시 여부와 흔들림(짧은 y 스케일 펄스) 계산, 충격파 고리 메시(RingGeometry, 투명도 감쇠) 1개 재사용, dispose 에 포함 |
| `src/features/city/city.css` | 버튼 활성 상태, 요약 줄, 단계 제목 스타일. 기존 `.sec`·`.item` 재사용 |
| `src/features/viewer-env.ts` | `Selection` 에 `blast?: boolean` |
| `src/features/shell/hash.ts` | `blast` 파싱·출력, `file` 없으면 `blast` 도 버림 |

- 파일명·경로는 기존과 같이 `esc()` 를 거쳐 넣는다.
- 애니메이션은 기존 렌더 루프 안에서만 돌고, 마지막 단계가 다 칠해지면 매 프레임 색 갱신을 멈춘다.

## 7. 위험

- 중심 파일은 도시 대부분이 영향권이 될 수 있다. 이것 자체가 보여 줄 정보이므로 제한하지 않는다. 대신 요약 %를 먼저 보여 준다.
- 파일 수천 개에서 프레임마다 전체 색을 다시 쓰면 느릴 수 있다 → 단계가 바뀌는 순간에만 색을 다시 쓰고, 흔들림은 해당 단계 건물 행렬만 갱신한다.
